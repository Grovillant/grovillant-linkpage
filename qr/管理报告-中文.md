## 现状和改进

现有五条是 HTML meta refresh + JavaScript 跳转；原脚本覆盖根目录文件，只有品牌有 SVG，PNG 带中心 logo。本包补齐六套矢量源文件和 600dpi PNG，采用同一个矩阵、H 容错、六格白边，码内不放 logo。原有带 logo 的历史文件保留；新印物料用交付目录中的黑白版，logo 放白边外。

五条旧路径永久兼容：pkg/manual/card 的 medium=print，fair=offline，ad=paid；source 都是 qr，campaign 是原路径名。目标保持 https://grovillant.com/ 加原 UTM。

qr/registry.json 是目标与管理信息的唯一来源，记录负责人角色、状态、首次登记/审核日期、版本、变更记录、替代 URL、不可停用、回滚说明。旧物料首次印刷日期无法推断，已明确写为待补录；老板还需指派具体接手人。

本地 vercel.json 准备了可调整的 307 跳转；q/*/index.html 保留原方式的备用跳转。没有碰线上 Vercel 设置。307 避免把今后会变的目标当作永久缓存；二维码中的稳定路径不变。任何托管迁移都先迁入同域名与旧路径，再切换，不能把二维码绑到个人账号或临时服务。域名自动续费、企业账号、备份和交接需品牌负责人落实。

## 统计和隐私

渠道码已具备稳定归因标记；统计的是到达页面的访问，不能当成准确的物理扫描次数或独立人数。重扫、机器人、网络失败、拦截统计脚本都会影响数字。

现有首页已加载 Vercel Analytics。但“参数在地址栏”不代表后台已经支持按 UTM 看报表。Vercel 的 Pages 报告不含查询参数，UTM 分组和套餐/功能有关，必须在真实项目中验收。官方参考：https://vercel.com/docs/analytics/using-web-analytics 和 https://vercel.com/docs/analytics/filtering 。本次没有读取项目后台，不能声称已看到五渠道报表，也没有擅自升级套餐。

已准备本地 qr-analytics.js（随跳转脚本从注册表生成），在统计前仅保留注册表允许的完整 UTM 组合，剔除其他查询参数与 hash；未知页面/外域事件直接丢弃。它不使用 cookie、localStorage、用户 ID 或个人扫码档案。不会修改客户地址栏，也不影响联系按钮。过滤只约束本页面传给 Analytics 的 URL，不能承诺第三方或托管平台完全不处理网络元数据。隐私页本地已更新，并在首页加了入口；上线后才生效。

上线验收需在受支持的统计配置下，分别用五条渠道做测试访问，确认渠道汇总可区分、参数正确；保存合计结果，不导出个人记录。若套餐不支持 UTM，另行批准合适的聚合分析方案（或支持的套餐），不能把“已贴 UTM”当成统计验收通过。参考：https://vercel.com/docs/analytics/redacting-sensitive-data 。

## 印刷、巡检与失效处置

完整中文印刷规范在交付包：SVG 优先、PNG 备用、保持白底白边、不拉伸裁切、不在码上加 logo；按真实纸样与距离验收。六格白边高于 DENSO WAVE 所述四格要求：https://www.qrcode.com/en/howto/code.html/index.html 。尺寸只是试印起点，以实物通过为准。

首批每种物料在前中后段抽检；换纸/覆膜/尺寸或加印重验。每月首个工作日巡检入口、UTM、落地页、WhatsApp 和 Email；改链接后当日及次日复检。失败先把跳转恢复到已知可用品牌页并保留 UTM，再修目标页，不能删除旧路径。
